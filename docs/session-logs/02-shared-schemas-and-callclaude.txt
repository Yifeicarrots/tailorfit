     Context

     Issue #1 is the shared foundation. The teammate is blocked on two parts:
     the Zod contracts in lib/types.ts and the callClaude wrapper with its model
     constant. This step does only those two. Storage (lib/storage/) and demo
     sign-in come in step 2. The rewrite result uses the full shape the issue
     asks for, plus the fields the teammate requested for #7 in their comment on
     #1.

     File layout

     lib/
       types.ts           # shared Zod schemas + z.infer types (contract, no 
     server-only)
       types.test.ts
       config.ts          # export const CLAUDE_MODEL = "claude-sonnet-5-5"

     Schemas (lib/types.ts)

     Every string is .min(1) unless noted. Exported types use z.infer.

     bulletSchema = z.object({ id: z.string().min(1), text: z.string().min(1) })

     experienceSchema = z.object({
       id: z.string().min(1),
       type: z.enum(["experience", "project"]),
       title: z.string().min(1),
       organization: z.string().min(1).optional(),  // projects may have none
       startDate: z.string().regex(/^\d{4}-(0[1-9]|1[0-2])$/),          // 
     "YYYY-MM"
       endDate: z.string().regex(/^\d{4}-(0[1-9]|1[0-2])$/).nullable(), // null 
     = present
       bullets: z.array(bulletSchema).min(1),
     })
     experienceLibrarySchema = z.array(experienceSchema)

     selectionResultSchema = z.object({
       selected: z.array(z.object({ id: z.string().min(1), reason:
     z.string().min(1) })),
     })

     // App-level contract: #6 (rewriter + validation) produces it, #7 
     (comparison screen) consumes it
     rewriteResultSchema = z.object({
       items: z.array(z.object({
         id: z.string().min(1),
         bullets: z.array(z.object({
           id: z.string().min(1),
           original: z.string(),
           rewritten: z.string(),
           flagged: z.boolean(),
           flagReason: z.string().min(1).optional(),
         })),
       })),
     })
     Exported types: Bullet, Experience, ExperienceLibrary, SelectionResult,
     RewriteResult.

     Rewrite contract boundaries
     - rewriteResultSchema is the app-level contract. #6 produces it and #7
       consumes it.
     - Claude's raw rewrite response is not in lib/types.ts. #6 parses it with
       its own minimal schema, which holds only the bullet ID and the rewritten
       text. That schema lives in the rewriter (lib/pipeline/resumeRewriter.ts),
       outside this issue.
     - Only our validation code sets flagged and flagReason. Claude never sets
       them. original comes from the library. #6 assembles the full result.

     Out of scope for the schemas, and left to validate.ts: ID uniqueness,
     unknown IDs, and dropped bullets. Those checks need the input, so a schema
     can't do them.

     lib/claude.ts

     - import "server-only". It is the only file that imports @anthropic-ai/sdk.
     - createCallClaude(client) takes a narrow client ({ beta: { messages: { 
       create } } }, typed from the SDK) and returns (system: string, prompt: 
       string) => Promise<string>. This makes it testable without network.
     - callClaude(system, prompt) builds new Anthropic({ apiKey }) on first use.
       If process.env.ANTHROPIC_API_KEY is missing it throws a clear error.
       Building on first use means imports never throw.
     - Request: client.beta.messages.create({ model: CLAUDE_MODEL, max_tokens: 
       16000, system, messages: [{ role: "user", content: prompt }], betas: 
       ["server-side-fallback-2026-07-01"], fallbacks: "default" }). Thinking is
       left at the model default (adaptive). There is no prefill.
     - Response handling: on stop_reason === "refusal" it throws. On
       "max_tokens" it throws, because truncated JSON is useless. Otherwise it
       returns the text blocks joined together. If there is no text, it throws.
     - It never logs prompts or responses. Error messages hold only the stop
       reason or category, never any content.
