  How checkNoInvention(original, rewritten) works (lib/pipeline/validate.ts):
  - Numbers: any number in the rewrite that isn't in the original is rejected,
    for example 40%, 150, or the 3 in 3-day.
  - Skills and employers: a word in the rewrite that isn't in the original is
    flagged if it looks like a name. That means it contains +, # or an inner dot
    (C++, Node.js), or it's an acronym (SQL), or it's capitalised anywhere
    except the first word (React, Northwind). Matching ignores case and
    surrounding punctuation, so react in the original allows React in the
    rewrite.
  - It returns { ok: true }, or { ok: false, problems } with one plain sentence
    per problem. Those sentences are ready to send back as the retry feedback.

  In the skills red commit, two of the seven new tests passed straight away.
  They check that the first word of a bullet and words reused from the original
  aren't flagged, so the heuristic couldn't flag too much. The commit message
  says so.

  Known gaps in the heuristic. Each would be its own red cycle if you want it
  fixed:
  - A skill written in lowercase isn't caught, e.g. "using docker".
  - A capitalised word after a full stop in the middle of a bullet is wrongly
    flagged.

         right column shows the original. Accept keeps the original; Edit is
         allowed.
