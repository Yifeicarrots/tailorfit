     Context

     Step 1 of issue #1 (shared Zod schemas in lib/types.ts, callClaude,
     CLAUDE_MODEL) is merged. Remaining checklist items: localStorage-backed

     export type KeyValueStore = Pick<Storage, "getItem" | "setItem" |
     "removeItem">;

     loadLibrary(store): ExperienceLibrary          // [] on missing / bad JSON 
     / schema fail
     saveUserName(store, name: string): void
     loadUserName(store): string | null             // null on missing / bad 
     data
     clearUserName(store): void
     - Keys: tailorfit:library, tailorfit:userName. Values stored as JSON.
     - Reads validated with experienceLibrarySchema from lib/types.ts
       (unchanged); name validated with a local z.string().min(1) (no change to
       shared schemas).
     - Tests use an in-memory fake KeyValueStore (a Map-backed object in the
       test file). Fixture experiences are fictional.

     TDD cycles (each: red commit → run & show failure → green commit → run & 
     show pass)

     1. Save then load the library returns the same data — test(storage): [red] 
        save and load the experience library / feat(storage): [green] …
     2. Load with nothing stored → []
     3. Load corrupted JSON → [], no throw (try/catch around JSON.parse)
     4. Load data failing the Zod schema (e.g. experience with no bullets) → []
        (safeParse)
     5. Save, load, clear the demo user's name (load after clear → null)
     6. (small extra, to keep "only lib/storage touches localStorage")
        browserStore() returns window.localStorage — tested with vi.stubGlobal,
        so the UI never references localStorage itself.

     Refactor commits only if real duplication appears (likely candidate: a
     shared readJson(store, key, schema, fallback) helper once cycles 3–5 exist
     → refactor(storage): extract validated JSON read helper).

       a client leaf app/DemoSignIn.tsx ("use client").
     - Signed out: name input + "Continue as demo user" button (disabled while

       name.trim()).
     - Signed in (also after reload): "Welcome back, {name}", count of saved

       state.

       match the Tailwind style of app/review/.
     - Update layout.tsx metadata title/description to TailorFit.
     - Commit: feat(signin): demo sign-in with name saved to local storage.
